# TABsucks 前端开发改造方案

版本：v1.0 正式稿  
制定日期：2026-09-29  
适用范围：本地浏览器前端及必要的小范围 Python HTTP 接口配套。  
文档用途：作为页面设计、开发拆分、联调和验收的统一基线。  
实施状态：本版功能已实现，自动回归与可控浏览器验证完成；发布前人工门槛及详细证据见[交付与验证记录](frontend-redesign-implementation.md)。本稿保留开发前的现状分析作为需求依据。

## 1. 目标与正式决策

将现有四步流程逐步改造成简洁的音乐工作台，让用户围绕同一首歌曲完成导入、分离、试听、分析、对照练习与导出。

目标是减少来回切页、让结果及时可用，并建立一致的视觉与交互规则。本文规定各阶段目标与完成条件，实际交付以对应阶段的验收记录为准。

| 设计决策 | 正式方向 | 状态 |
|---|---|---|
| 首要场景 | 分离与导出、扒谱与练习同等重要 | 用户已确认 |
| 改造方式 | 分阶段交付：先统一视觉，再整合试听与分析 | 用户已确认 |
| 视觉与设备 | 电脑端优先，深浅色跟随系统设定 | 用户已确认 |
| 用户术语 | 界面将“车间”称为“项目”，内部数据名称保持兼容 | 用户已确认 |
| 实现方式 | 沿用现有原生 JavaScript 模块及 Python 服务 | 用户已确认 |
| 后端边界 | 优先复用接口；必要的小范围接口配套单独列项 | 用户已确认 |

两条核心路径均须直接可达：导入 → 分离 → 试听检查 → 导出音轨；导入 → 分离 → 分析目标音轨 → 对照练习 → 导出 MIDI。下载已生成音轨不要求先做和弦分析，练习也不要求先导出文件。分期是实现顺序，不代表降低任一场景的产品优先级。

### 1.1 统一术语

| 用户可见名称 | 含义或内部映射 |
|---|---|
| 项目 | 一首歌曲及其音源、分轨、分析结果；内部继续使用 workshop |
| 原曲 | 导入的完整音频；接口使用明确的原曲标识 |
| 音轨 | 分离得到的人声、鼓、贝斯、钢琴、吉他、其他声部 |
| 加入分析 | 将音轨加入批量分析范围，不改变播放混音 |
| 静音 / 独奏 | 控制听到的音轨，不改变分析或导出选择 |
| 下载音轨 | 下载实际生成的音轨音频文件 |
| 导出 MIDI | 将选定的有效和弦结果导出为 MIDI，不表示完整音符转录 |
| 关闭项目 | 结束当前激活状态，项目仍保留 |
| 删除项目 | 永久删除项目，操作前明确确认 |

页面不再显示 Tab1–Tab4、run、next 等内部或混用文案。分期一保留四步交互，显示为“导入音频、分离音轨、分析音轨、播放与导出”。模型和插件专有名称保留原名。应用产生的错误摘要使用“项目”，原始技术详情可折叠查看，不对服务端文本做不可靠的全局替换。

### 1.2 产品完成目标

- 用户能不经过分析直接试听和下载分离音轨。
- 用户能在同一工作台完成分析与对照练习，单条失败不阻塞其他可用结果。
- 系统深浅主题均完整可用，切换主题不会中断播放或任务。
- 旧项目继续可读，关键设置和结果的有效性有明确边界。
- 当前状态、下一步操作和失败后的处理方式始终可理解。

## 2. 当前实现与改造依据

以当前源码为实现依据；历史说明文档中的规划能力不视为已完成能力。

| 当前事实 | 对改造的影响 |
|---|---|
| 纯黑背景、白色外框、全局等宽字体；中英文操作文案混用 | 统一颜色、字号、间距、控件与中文文案 |
| 无活动项目时，欢迎内容位于侧栏，主要内容面板隐藏 | 欢迎页移到主区域，提供导入和打开已有项目入口 |
| 播放页入口要求所有已选音轨分析完成 | 将音频可播放条件与分析完成条件分离 |
| 每次加载播放页会销毁播放器并重置时间 | 播放器生命周期应绑定项目与音源，而不是面板切换 |
| 音轨可视化接口支持没有和弦结果时返回波形 | 未分析音轨可显示波形及“尚未分析”状态 |
| 当前音频路由对缺失音轨会回退到原始音频 | 不可直接据此判断分轨可用；缺失分轨必须明确报错，避免把原曲误当分轨 |
| 已有任务查询、取消及事件推送 | 复用任务体系，增加持久状态区和断线后的状态核对 |
| 核心层已有混音状态，当前 HTTP 路由未提供对应更新接口 | 浏览器内混音与跨重启保存要分别安排 |
| 项目列表只有名称、标识、最后页及激活状态等字段 | 完整历史项目状态、最近修改时间需要额外信息，不虚构排序或状态 |
| 当前播放由多个音频元素共同驱动 | 增加混音、变速和循环时验证同步与漂移；不提前承诺专业编辑器级精度 |
| 部分测试直接检查四步页面结构和脚本字符串 | 页面重组时更新过时断言，并补充真实用户行为验证 |

主要涉及文件：`src/ui/static/index.html`、`src/ui/static/css/`、`src/ui/static/js/`，以及配套的 `src/ui/api/`。

## 3. 范围与交付边界

### 首个可交付版本：分期一

- 统一视觉样式、文案、按钮层级、焦点与禁用状态。
- 同时提供深浅两套语义颜色，首次打开和运行中均跟随系统主题。
- 主区域欢迎页、拖放上传、项目重命名与更多菜单。
- 保留当前四步结构，明确区分当前步骤、已完成步骤和未就绪步骤。
- 上传、分离、分析的运行、取消、失败反馈可持续查看。
- 倍速改为明确可选择的控件。
- 不改变模型推理、任务调度、缓存格式及已有结果。

### 工作台版本：分期二

- 将试听、音轨选择、分析配置与结果放在同一工作区。
- 原曲导入后可试听；分离音轨就绪后可试听，无需先完成分析。
- 分析逐轨完成、逐轨展示，单条失败不阻塞其他可用音轨。
- 同一项目内切换面板保留播放器状态。
- 提供逐轨静音、独奏、音量及准确的 MIDI 导出可用性。
- 提供已生成音轨的单轨下载入口；音频导出和 MIDI 导出明确区分。
- 兼容旧项目的页面恢复；处理事件断线、重跑、切换项目等边界。

### 练习增强：分期三

- A–B 循环、选中和弦定位、播放头跟随与快捷键说明。
- 同一次浏览器页面会话中按项目保留练习设置；跨刷新、跨重启保存不纳入本版。
- 依据分期二实测结果改善多轨同步、波形刷新与加载性能。

本轮不包含完整 DAW、音频剪辑、手工和弦编辑、模型精度优化、账号系统、云端存储、插件市场或完整手机工作台。单轨音频下载纳入分期二；批量 ZIP 下载及混音后音频导出作为可选后续项，不与已有 MIDI 导出混称为同一能力。

## 4. 页面与信息架构

### 4.1 欢迎与导入

主区域展示简短说明、主要动作“导入音频”和次要动作“从链接导入”。支持拖放一个文件，文件类型与大小校验以实际服务端能力为准。

无项目时说明开始方式；有历史项目时可从侧栏继续。本版不增加最近修改时间字段，不标“最近使用”，列表保持接口返回顺序。导入成功显示文件名、真实可读的时长及“开始分离”，尚未取得时长时显示加载状态，采样率放在详细信息内。

“新建项目”先打开导入界面，选择本地文件或提交有效格式的链接后再创建项目，避免取消选择后留下空项目。新建入口始终创建新项目；在当前项目更换音源必须使用单独的“更换音源”操作。上传失败时保留已创建的项目及重试入口，不擅自删除。

当前后端在成功提交新音源时会重置分离状态、清空分析及混音状态。更换前明确提示“更换后需重新分离和分析”，新音源提交成功后重置当前项目播放器和练习设置。提交失败不提前清空界面已有结果，重新查询项目确认实际状态。

### 4.2 项目侧栏

- 顶部：应用名、新建项目；中部：项目列表。未实现的应用级设置不放占位按钮。
- 每项显示名称、选中状态；任务状态仅在有可靠数据时显示。
- 重命名、关闭、永久删除放入可通过键盘访问的更多菜单。
- 永久删除的确认框明确显示项目名和删除后果；关闭与删除采用不同文案。
- 窄窗口侧栏折叠为抽屉，避免持续占用工作区宽度。

### 4.3 音乐工作台

| 区域 | 内容与行为 |
|---|---|
| 顶栏 | 项目名、歌曲信息、任务状态入口、导出菜单（音轨文件 / MIDI） |
| 分离设置面板 | 当前模型、运行设备、开始或重新分离；准备分离时展开，音轨就绪后收起 |
| 音轨工作区 | 原曲与实际可用分轨、轨名、静音/独奏/音量、波形、分析状态 |
| 分析设置面板 | 当前音轨、适配的分析插件、批量分析范围、开始/重试；与音轨行保持关联 |
| 和弦层 | 对应音轨的有效结果、未分析或失败说明；可折叠 |
| 底部播放器 | 播放/暂停、当前时间/总时长、定位、倍速；分期三增加循环控制 |

原曲与分轨采用“原曲 / 分轨”试听切换，两者互斥。切换时保留当前时间和播放/暂停意图；目标音源尚未就绪时先暂停并显示加载，准备完成后仅在该项目和当前播放意图仍有效时继续。分轨混音设置不因试听原曲而丢失。初始主工作区展示实际可用分轨，不为缺失分轨绘制伪波形。

工作台同时服务两种任务，不增加强制的“制作模式/练习模式”切换。音轨行提供试听与下载，分析面板提供加入分析与结果查看；顶栏导出菜单按产物类型组织。

## 5. 核心交互规则

### 5.1 三种选择分别表达

- **当前查看音轨**：用于打开分析配置和查看结果。
- **待分析音轨**：批量任务范围，对应现有已选音轨状态。
- **参与试听的音轨**：由静音、独奏和音量控制；不自动改变分析选择。

界面用“加入分析”表达批量选择，不用没有上下文的“选中”同时承担所有含义。第一版 MIDI 导出范围为已加入分析且具有可导出和弦结果的音轨子集，以兼容现有接口约束。

新生成分轨默认不加入分析，避免意外启动全轨计算；试听默认启用全部实际可用分轨。旧项目恢复已有分析选择。“全选可分析音轨”仅选择存在适配插件的音轨，且不会自动开始任务。批量按钮明确写“分析所选 N 条音轨”，继续复用现有串行队列及冲突限制。

### 5.2 可用性按动作判断

| 状态 | 允许操作 | 不可用操作的说明 |
|---|---|---|
| 尚未导入 | 导入音频或链接 | 分离：请先导入音频 |
| 原曲就绪 | 原曲试听、选择模型、开始分离 | 分轨试听：尚未生成音轨 |
| 分离处理中 | 查看任务、请求取消；原曲仍有效时试听 | 重复分离或冲突分析：当前任务尚未结束 |
| 分轨就绪、未分析 | 分轨试听、混音、下载音轨、选择并启动分析 | MIDI：尚无可导出的和弦结果 |
| 部分分析完成 | 继续试听、查看已完成结果、导出符合条件的子集 | 未完成轨道显示各自状态 |
| 分析失败或取消 | 保留其他结果、查看原因、按条件重试 | 不将取消或失败当作成功 |
| 文件缺失 | 显示缺失音轨与恢复建议 | 禁止以原曲冒充分轨播放 |

浏览器按钮状态只用于引导，服务端仍是任务冲突和数据有效性的最终判断。收到冲突响应后重新拉取状态并解释原因。

### 5.3 播放与练习

- 底部播放器仅在存在可播放音源时出现；同一项目内开关设置面板不重置播放。
- 切换项目时暂停旧项目，确认切换成功后加载新项目；失败时显示错误并保持可理解的原项目状态。
- 同一会话切回已打开项目时恢复时间和混音设置，但默认暂停，不自动出声。页面刷新或服务重启后恢复已有持久化业务数据，播放时间回到起点、倍速为 1×、循环关闭。
- 倍速第一版提供 0.5×、0.75×、1×、1.25×、1.5×、2×；默认保持音高，列入目标浏览器的听感验收。
- 单轨音量范围 0–100%，默认 100%；独奏允许多条，有独奏轨时仅播放这些轨，静音优先于独奏。按钮名称及按下状态需可访问。
- A–B 循环要求 A < B，超出时长时校正；展示起止时间，提供启用、停用和清除。
- 点击有效和弦块定位到其开始位置，默认不改变暂停状态；循环仅在显式设置并启用后生效。无结果、占位信息和过期结果不作为定位数据。
- 自动跟随播放头允许关闭；用户手动浏览时间轴时不强行拉回。
- 空格播放/暂停，输入框、下拉框、按钮及可编辑区域优先保留原有键盘行为。

### 5.4 任务、失败与恢复

- 状态区显示准备、执行、完成、失败或取消；只有服务端真实提供阶段时才细分“加载模型”等阶段。
- 未提供可计算进度时使用不定进度，不补造百分比或剩余时间。
- 取消后先显示“正在取消”，以服务端终态确认完成。
- 普通成功提示可短暂显示；任务失败在任务区域保留原因和可用操作。
- 事件流断线时显示连接状态；恢复后查询项目和任务，避免只依赖未必会重放的事件。
- 不承诺切换项目后任务继续后台执行；遵守现有切换、关闭及任务管理语义。
- 重新分离前提示“成功后将替换音轨，并清空分析选择、分析结果及混音设置”。该行为对应当前分离完成逻辑；运行期间停用旧分轨试听、下载与分析，原曲仍有效时可试听。失败或取消后查询实际状态，不承诺旧文件一定可恢复；本版不增加结果版本回滚功能。
- 分离成功后清理旧播放器、波形、混音和练习设置，重新读取实际音轨；任务失败时不伪造完成状态以绕过数据校验。

### 5.5 导出规则

| 导出类型 | 范围与前置条件 | 输出规则 |
|---|---|---|
| 音轨音频 | 已生成且当前可用的单条分轨，无需分析 | 原始分轨文件，音量、静音、独奏及倍速不会改变下载内容 |
| MIDI | 当前加入分析、具有有效和弦结果且不在相关重跑中的音轨子集 | 和弦 MIDI；导出面板列明所用音轨与结果来源 |

音频下载按钮位于音轨行，顶栏菜单提供同一能力的集中入口。MIDI 面板默认勾选符合条件的轨道，其他轨道说明不可用原因。用户可以取消部分勾选；零条时禁用导出。不存在、失败或过期结果不可静默跳过后宣称全部导出成功。

导出使用的分析结果必须与界面当前展示的结果一致。选择新插件但尚未运行时，旧结果如保留显示，需标明旧插件来源，不能当作新插件已完成。相关重跑期间禁用该轨 MIDI 导出，完成后重新核对可用结果。

下载文件名包含项目名和音轨名，去除非法文件名字符。原曲使用实际格式与正确媒体类型，不把所有原曲一律标为 WAV。浏览器仅已发起下载时提示“已开始下载”，不声称文件已保存到磁盘；HTTP 失败显示明确错误，不生成伪音频或伪 MIDI 文件。

## 6. 视觉与响应式规范

系统跟随深浅色为已确认需求。使用语义化颜色变量覆盖背景、文字、边框、悬停、焦点、禁用、状态和音轨结果；通过 `prefers-color-scheme` 初始化并监听运行中的系统变化。原生表单、菜单与滚动条设置对应 `color-scheme`。第一版不增加手动主题覆盖，避免与“跟随系统”产生歧义。

主题切换只更新表现，不暂停播放、不清空时间轴、不重建任务。Canvas 波形和播放头同步重绘，不能只切换页面 CSS。字体使用本地系统字体，避免主题加载和外部字体造成首次显示闪烁。

| 项目 | 初始规范 |
|---|---|
| 页面背景 | 深色 `#111318`；浅色 `#F5F6F8` |
| 面板背景 | 深色 `#191D25`；浅色 `#FFFFFF` |
| 正文颜色 | 深色 `#E8ECF2`；浅色 `#202630` |
| 分隔线 | 深色 `#2A303C`；浅色 `#DDE2EA`，减少完整外框 |
| 主色 | 延续蓝紫色，主要用于主按钮、焦点、选中状态 |
| 正文 | 系统无衬线中文字体，14–15px；无需联网加载 |
| 辅助文字 | 12–13px；时间和数字使用等宽字体 |
| 间距 | 4、8、12、16、24、32px 为基础档位 |
| 圆角 | 控件 6–8px，面板 10–12px |
| 控件高度 | 常用操作约 36–40px，密集轨道操作仍保留充分点击区域 |
| 音轨色 | 沿用已有分类含义，按深浅背景调整明度，集中用于色条、波形和结果标识 |
| 状态 | 颜色同时配合文字或图标，禁用状态提供原因 |

普通正文对比度以至少 4.5:1 为验收目标，焦点可见。表中颜色作为实现起点，可在满足对比度与两种主题一致性的前提下微调并记录，不改变已确认的系统跟随策略。动画只用于状态衔接，遵循减少动态效果的用户设置。

桌面验收尺寸为 1440×900、1366×768、1024×768，以浏览器内容视口计。宽度小于 1200px 时侧栏默认折叠为抽屉，分析设置改为按需展开，工具栏允许换行，页面主体不产生横向溢出。时间轴内部允许横向滚动，轨名栏与统一时间标尺保持可见。深色和浅色分别验收文字、波形、和弦块、禁用态与焦点；手机完整操作不纳入范围。

正文、按钮和时间数字在长项目名、125% 系统缩放和浏览器缩放后不得相互遮挡。缩放导致视口变窄时使用相同的折叠规则。菜单和对话框支持 Escape 关闭并将焦点还给触发控件；图标按钮具有名称，弹窗内焦点顺序合理，不能仅靠悬停发现主要操作。

## 7. 技术拆分与接口依赖

### 7.1 前端结构

沿用当前模块，不因视觉改造直接引入新框架或构建链。逐步明确以下职责：

- 应用外壳：项目切换、导航、欢迎页与工作台布局。
- 项目数据与任务状态：以接口为依据，事件更新后可查询校正。
- 播放器：管理音源、时间、倍速、混音和循环；不依赖当前显示哪个面板。
- 音轨与分析视图：渲染轨道和结果，状态变化不重建全部音频元素。
- 通用控件：按钮、表单、菜单、对话框、状态反馈、空态。
- 样式：统一变量和组件规则，减少持续向覆盖文件追加互相冲突的规则。

异步加载保留项目标识与请求版本核对，忽略切换项目后的过期响应；分析结果按轨道与插件对应，防止换模型后显示错误的“已完成”。波形缓存按项目、音轨和音源版本区分，重新分离后失效。

### 7.2 接口复用与缺口

| 能力 | 当前基础 | 方案 |
|---|---|---|
| 项目重命名 | 已有接口 | 直接接入 |
| 上传、分离、分析、任务取消 | 已有接口 | 保留协议，重做呈现 |
| 无和弦时查看波形 | 可视化接口已支持 | 解开前端流程限制，按元数据区分缺失音频与未分析 |
| 缺失分轨反馈 | 音频路由会回退原曲 | 分期 2A 必须将原曲读取和具体分轨读取明确区分，补充接口回归 |
| 部分 MIDI 导出 | 接口接受已选轨的子集，并校验结果 | 导出面板明确可用、不可用轨道，不默默漏导 |
| 单轨音频下载 | 已有音频响应，但当前是行内播放响应且存在原曲回退 | 验证真实分轨后提供明确下载语义、正确文件名和失败提示；优先复用文件响应，避免大文件全量读取到浏览器内存 |
| 可视化与导出结果一致性 | 当前接口按轨读取最新成功和弦结果，缺少显式结果选择契约 | 分期 2B 返回结果来源标识，并让导出校验同一标识；多个插件或重跑后不混用 |
| 静音/独奏/音量 | 核心层有状态；当前 UI API 未暴露更新入口 | 分期二使用会话控制，初次打开可读取已有有效混音值；本版不新增混音写入接口 |
| 项目列表任务摘要与排序 | 列表字段不足 | 本版不扩展列表接口；只对已获取的当前项目显示可靠状态，不逐项目加载大状态 |
| GPU 可用性 | 当前 UI API 未提供独立设备能力接口 | 保留手动选择及真实失败提示；本版不加入自动设备推荐 |
| 练习设置保存 | 当前 API 未提供完整协议 | 同次页面会话按项目保留；跨重启保存列入后续范围 |

后端配套限定为音频资源语义、下载响应、结果来源与一致性校验，以及落实这些能力所需的少量元数据；不更换模型、不调整调度策略、不改缓存目录和既有结果文件格式。范围内变化需保持现有合法请求可用，并同步修改定向测试及 HTTP API 文档。跨重启设置保存、完整项目状态摘要和自动设备推荐不属于本版必做任务。

### 7.3 旧项目兼容

后端仍使用现有 `LastTab` 及 Tab1–Tab4 存储结构。新版增加视图映射：Tab1 打开导入或音源面板，Tab2 打开分离区，Tab3 打开分析区，Tab4 打开时间轴。数据不满足条件时展示对应空态及恢复入口。

新版打开导入、分离、分析或时间轴主面板时分别写回 Tab1、Tab2、Tab3、Tab4；打开临时菜单、对话框或切换轨道不改写 LastTab。写入串行化并核对项目标识，避免晚到请求覆盖新项目状态；保存失败显示非阻塞提示并可重试，不把失败显示为已保存。用四种旧项目样例验证恢复。仅重命名界面术语不迁移缓存目录或重写历史分析结果。

### 7.4 数据与播放器生命周期

| 状态类别 | 保存位置 | 有效期与恢复规则 |
|---|---|---|
| 项目名、音源、分离结果、分析结果、分析选择、LastTab | 现有服务端状态 | 依照当前接口保存，刷新和重启后重新读取 |
| 当前查看轨、时间轴缩放、试听来源、播放位置、倍速、混音、循环 | 浏览器内存，按项目隔离 | 同一页面会话切换项目后恢复；刷新或关闭页面后不保证保留 |
| 播放中状态 | 当前播放器实例 | 切换项目、刷新、关闭项目后均恢复为暂停 |
| 波形、分析视图缓存 | 浏览器内存 | 按项目、音源版本及结果标识区分；换源和重跑后失效 |
| 排队、运行、取消与终态 | 服务端任务记录为准 | 事件更新，重连或不一致时重新查询 |

已有项目中的有效混音值可作为首次加载默认值；没有值时使用全轨音量 100%、无静音、无独奏。界面不显示“混音已保存”或“练习设置已保存”等持久化承诺。

播放器从 `app.js` 的页面切换逻辑中分离，按项目和音源版本创建/销毁。销毁时停止动画、解除监听、释放音频资源；面板渲染和系统主题变化不销毁音源。媒体实际时间作为播放头依据，不能仅用动画帧累计时间模拟音频位置。多轨中部分加载失败时标明失败轨道，允许用户明确选择播放剩余轨道，不能默默缺轨仍显示全部就绪。

### 7.5 必要接口契约

以下为正式接口要求；实施结果与准确协议见交付记录及 `docs/HTTP_API.md`。

| 编号 | 契约 | 兼容与失败处理 |
|---|---|---|
| BE-01 | `GET /api/workshops/{wid}/audio/{track}` 明确支持 `full` 原曲及合法分轨；具体分轨缺失返回 404 | 去掉缺失分轨回退原曲；拒绝非法轨名和任意路径；媒体类型匹配实际文件，保留定位播放所需响应能力 |
| BE-02 | 为同一媒体路由增加可选 `download=true`，返回附件响应和可用文件名 | 默认仍用于播放；音源缺失返回现有格式的错误；浏览器使用下载请求，不把整个音轨加载为 Blob |
| BE-03 | 可视化响应增加结果来源标识和音源版本标识；允许按有效结果标识读取所选结果 | 旧请求仍能取得最新有效结果；无分析时返回空结果；无音频时明确标记不可用，不生成占位波形 |
| BE-04 | MIDI 请求可提交每条轨对应的结果标识，服务端验证项目、音轨、成功状态和当前音源有效性 | 新前端必须提交；旧调用保留现有默认规则；结果过期或不匹配返回 409 并要求刷新，不改导出别的模型 |

结果标识使用已有任务或分析记录中可稳定定位的标识，旧记录没有任务标识时采用可校验的不透明引用；不接受任意客户端文件路径。音源版本可从当前音频资源信息生成，不要求迁移历史缓存格式。准确字段名与查询编码由对应开发任务同步写入 `docs/HTTP_API.md`，契约语义不得改变。

新增接口能力继续遵守当前项目、任务及文件访问校验，不绕过业务冲突限制。结果选择和多轨导出使用同一结果解析逻辑，防止两处各自选择“最新”产生差异。

## 9. 验收与测试

### 必须覆盖的用户路径

1. 首次打开 → 导入本地音频 → 分离 → 无分析情况下试听。
2. 链接导入失败 → 查看原因 → 修改链接重试。
3. 一条音轨分析成功、另一条失败 → 成功结果仍可查看并导出有效子集。
4. 调整倍速和音量 → 切换同项目设置面板 → 时间与设置保留。
5. 切换项目或重跑分离 → 旧事件、旧波形及旧音频不污染新状态。
6. 请求取消 → 等待服务端终态 → 可按规则重试。
7. 事件断线后重连 → 状态与任务查询一致。
8. 打开旧项目 → 找到已有音轨、结果和合理的对应面板。
9. 音频文件缺失、无适配插件、空和弦结果 → 明确说明，其他可用轨道仍能使用。
10. 窄窗口和键盘操作 → 菜单、播放、导出和关闭对话框均可到达，焦点不会丢失。
11. 分离完成但未分析 → 下载指定音轨 → 文件与该轨一致，缺失时不下载原曲冒充。
12. 分别以系统深色、浅色打开 → 正确匹配；播放中切换系统主题 → 页面和波形同步更新，播放与任务不中断。
13. 同一轨道分别产生两个插件结果 → 界面选择并显示其中一个 → MIDI 使用同一结果；过期标识明确失败。
14. 更换音源或重新分离成功 → 旧分析选择、结果、混音和循环不残留；取消确认不发起重跑。
15. 页面刷新 → 服务端已保存数据恢复；不自动播放，不声称已恢复未持久化的练习设置。

### 验证方式

- 对调整的接口运行定向回归；保留项目激活、结果归属、任务取消及导出校验。
- 使用可控样例与任务状态验证界面，不要求每次界面测试重新执行真实模型。
- 对跨步骤试听、部分失败、切换项目等流程增加浏览器行为检查，替换已过时的页面字符串断言。
- 对欢迎页、运行中、部分完成、失败、长名称和窄窗口在深浅两种主题下逐项截图检查。
- 在目标 Windows 浏览器验证真实音频：播放、暂停、拖动、倍速、静音、独奏、循环与长时间同步。
- 同步验收目标：使用等长测试音轨，在 0.75×、1×、1.5× 下连续播放三分钟，每 30 秒记录各活动音轨相对主时钟的时间偏差，均不超过 50ms。循环测试取不少于 5 秒的区间连续运行十次，每次跳转稳定后 200ms 采样，轨间偏差不超过 50ms，且没有听感可辨的持续错拍。记录设备、浏览器和测量方式；前端时间采样不能替代听感检查。不要求采样级无缝循环。
- 如当前多音频元素方式达不到同步目标，先在播放器模块内改善同步；必要时调整前端音频实现，仍沿用既定应用技术栈。不得仅修改可视化播放头掩盖偏差，或未经变更记录降低验收目标。
- 使用约三分钟和十五分钟的真实音频、六条分轨记录首次波形加载、连续缩放滚动和内存表现。以同一设备的改造前后数据比较，不在无基准情况下承诺绝对加载时间。重复打开/关闭工作台二十次后不应残留多个事件连接、播放器或动画循环。

| AC-06 | 分期三 | 循环、定位、跟随及快捷键通过；同步指标与听感验收通过 |

每阶段只有在所属门槛及已交付阶段的关键回归均通过后才算完成。任何数据丢失、错误音源播放、错误分析结果导出或主流程不可用均为阻断问题；视觉问题如果导致关键控件不可读、不可达或主题不一致，同样阻断该阶段交付。

测试应验证用户行为和业务结果，不为纯配色调整堆砌实现镜像测试。已被新流程取代的字符串断言可以重写，但不能简单删除并失去相应业务覆盖。

## 10. 主要风险及处理

| 风险 | 处理要求 |
|---|---|
| 页面重组破坏原有恢复流程 | 保留存储结构及明确的 LastTab 映射，使用四类旧项目回归 |
| Canvas 保留硬编码颜色，浅色主题不可读 | 所有绘制颜色来自主题变量，系统切换时重绘并截图检查 |
| 分离重跑、换源或晚到响应留下旧结果 | 项目与音源版本隔离；成功后统一失效；服务端核对结果来源 |
| 多轨播放、倍速和循环出现漂移 | 先解耦播放器再增加练习能力，用实际音频和时间偏差验收 |
| 接口缺失轨道回退原曲导致错误下载或试听 | BE-01 必须先完成；缺失分轨明确返回错误 |
| 多插件结果选择不一致 | 视图与导出使用同一结果标识，过期时要求刷新 |
| 声称后台继续处理但实际任务已关闭或取消 | 保持现有任务语义，以查询终态为准，切换中显示明确等待状态 |
| 下载大文件占用过多浏览器内存 | 使用服务端文件下载响应，音轨下载不进行全量 Blob 缓存 |
| 改造范围扩散到完整音频编辑器 | 按本稿工作包交付，范围外需求单独登记 |

## 11. 交付、发布与回退

### 11.1 每阶段交付物

1. 对应工作包的前端代码及必要接口配套，附变化说明。
2. 深浅主题页面截图；涉及交互时附可运行的页面或原型。
3. 验收记录：环境、样例、执行结果、未解决问题及其影响。
4. 涉及接口或操作路径时，同步更新 `docs/HTTP_API.md`、用户流程说明及相关使用说明。
5. 本方案工作包状态与变更记录；未交付功能明确标识，不在产品里放可点击的假入口。

### 11.2 发布步骤

- 在开发分支内按工作包形成可审阅的提交，保留各阶段可回退的版本点。
- 分期一交付统一视觉后的四步界面；分期二在播放与恢复验证通过后交付工作台；分期三补齐练习增强。最终不长期维护两套正式 UI。
- 每次更新同步静态资源版本，确认浏览器没有混用新旧脚本和样式。
- 首次使用新版打开既有项目时验证读取和恢复，不执行批量缓存迁移、结果重写或模型重跑。
- 交付说明明确本阶段已有能力、会话设置保存边界及范围外功能。

### 11.3 回退原则

界面、播放器或接口出现阻断问题时回退对应代码版本，不删除用户项目、音源或分析文件。新增响应字段和可选参数尽量保持兼容；回退必须同时匹配前端和服务端版本，避免新界面调用旧接口。

改造不迁移旧数据格式，因此代码回退不以恢复整份缓存为前提。用户主动换源或重跑已造成的业务状态变化不因代码回退自动撤销；文案和交付说明不得承诺结果历史恢复。
