### 1. 地基：数据流与文件系统

数据流是处理音频、分析音乐和结果可视化的核心要素，没有数据无法分离分析以及可视化结果。文件系统是对用户历史数据的本地缓存，没有文件系统，用户分析的结果无法保存、覆盖、丢失，不能复用，降低用户体验、数据利用率低。


#### 数据流的设计

| 环节                        | 输入                                                   | 输出(内存)                         | 输出(文件系统)                    |
| ------------------------- | ---------------------------------------------------- | ------------------------------ | --------------------------- |
| URL → 本地                  | URL(str, 从 UI 层获取)                                   | 临时 wav                         | 音频 mp4/wav等格式，保存位置(str)     |
| 本地 → AudioData            | path(str, 文件系统)/ UI交互(选择本地文件) + path(str)            | AudioData                      | AudioData                   |
| AudioData → 分离模型 -> 6 道音轨 | AudioData(从内存)                                       | SeparationResult(Audio Data)   | 6条音轨的AudioData，对应的元信息(json) |
| 选择音轨、选择模型                 | UI 层：按钮交互/表单/下拉目录之类的                                 |                                |                             |
| 音轨 → 节奏                   | AudioData(从内存，或者从文件系统(str->AudioData))               | BeatInfo（节奏对应的特殊数据结构）          | 节奏对应的特殊数据结构，对应的原信息(json)    |

| 可视化                       | 音轨(从文件系统、内存)、分析结果(从文件系统、内存)、部分视觉元素(从文件系统、内存)         | UI 视觉元素与效果                     | 无                           |

### 5. 补充：UI ↔ 后端事件推送（SSE 极简版）

> 会议讨论之后的进一步讨论补充，2 周 MVP 阶段必须解决的关键点之一。

#### 5.1 为什么需要

走"本地服务 + HTML"路线后，前端无法直接订阅后端 Python 对象的变化。  
**若不解决**：前端只能靠 `setInterval` 轮询后端状态，会出现：
- 进度条每 2 秒跳一格（卡顿）
- 用户切到别的 Tab 时收不到"分离完成"通知
- 跑完模型后 UI 仍显示"未分离"，必须手动刷新
- 后端白白被轮询，浪费 CPU

**解决问题**：通过 **Server-Sent Events (SSE)** 让后端主动推事件到前端。

#### 5.2 事件总线设计（后端）

```python
# src/kernel/core/event_bus.py
from __future__ import annotations
import asyncio
from dataclasses import dataclass, field
from typing import Any, Literal

EventType = Literal[
    "separation_started",
    "separation_progress",   # payload: {progress: 0~1}
    "separation_done",       # payload: {stems: list[str]}
    "separation_failed",     # payload: {error: str}
    "analysis_started",      # payload: {track, plugin}
    "analysis_done",         # payload: {track, plugin, result_path}
    "analysis_failed",       # payload: {track, plugin, error}
    "stale",                 # payload: {tab, reason, keys: list}
    "playback_state",        # payload: {current_time, is_playing, speed, loop}
    "mix_state",             # payload: {track, mute, solo, volume}
]

@dataclass(frozen=True)
class WorkshopEvent:
    workshop_id: str
    type: EventType
    payload: dict = field(default_factory=dict)
    emitted_at: float = 0.0   # time.time()

class EventBus:
    """进程级事件总线。MVP 阶段单进程足够。"""
    def __init__(self) -> None:
        self._subscribers: dict[str, list[asyncio.Queue]] = {}

    def subscribe(self, workshop_id: str) -> asyncio.Queue:
        q: asyncio.Queue = asyncio.Queue()
        self._subscribers.setdefault(workshop_id, []).append(q)
        return q

    def unsubscribe(self, workshop_id: str, q: asyncio.Queue) -> None:
        if q in self._subscribers.get(workshop_id, []):
            self._subscribers[workshop_id].remove(q)

    def emit(self, event: WorkshopEvent) -> None:
        for q in self._subscribers.get(event.workshop_id, []):
            q.put_nowait(event)
```

#### 5.3 极简版（MVP 阶段，0.1 人天可落地）

为节省工时，**MVP 阶段只推送 4 个关键事件**，其余走轮询：

| 事件 | 推送理由 | 接收方 UI 反应 |
|------|----------|---------------|
| `separation_done` | 跑完才能进入 Tab3 | 刷新 Tab2 stem 网格 + 启用 Tab3 按钮 |
| `analysis_done` | 跑完才能用结果 | 刷新 Tab3 列表 + 启用 Tab4 关联 |
| `separation_progress` | 进度条要丝滑 | Tab2 进度条 0.1s 更新一次 |
| `analysis_failed` | 失败要立即提示 | 弹窗：错误信息 + 重试按钮 |

**事件总线集成点**：
- `SeparatorPlugin.run()` 内周期性 `bus.emit(WorkshopEvent("separation_progress", {"progress": p}))`
- `AnalysisPlugin.run()` 完成后 `bus.emit(WorkshopEvent("analysis_done", {...}))`
- `Workshop.run_separation()` 包裹一层 try/except，捕获异常后 `bus.emit(..., "separation_failed", ...)`

#### 5.4 HTTP 端点（FastAPI 示例，纯 stdlib 也可）

```python
# src/ui/http_server.py
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import json

app = FastAPI()
bus = EventBus()

@app.get("/api/workshops/{wid}/events")
async def events(wid: str):
    q = bus.subscribe(wid)
    async def gen():
        try:
            while True:
                ev = await q.get()
                yield f"data: {json.dumps({'type': ev.type, 'payload': ev.payload})}\n\n"
        finally:
            bus.unsubscribe(wid, q)
    return StreamingResponse(gen(), media_type="text/event-stream")
```

> 不依赖 FastAPI 的话，可以用 `http.server` + 手写 SSE 协议，约 50 行。

#### 5.5 前端订阅（浏览器原生 EventSource）

```javascript
// src/ui/static/js/event_stream.js
class WorkshopEventStream {
    constructor(workshopId) {
        this.source = new EventSource(`/api/workshops/${workshopId}/events`);
        this.source.onmessage = (e) => this._handle(JSON.parse(e.data));
    }
    _handle(event) {
        switch (event.type) {
            case 'separation_progress':
                document.getElementById('sep-progress').value = event.payload.progress;
                break;
            case 'separation_done':
                refreshStemGrid(event.payload.stems);
                enableTab3();
                break;
            case 'analysis_done':
                refreshAnalysisList(event.payload.track, event.payload.plugin);
                break;
            case 'separation_failed':
                showErrorModal(event.payload.error);
                break;
        }
    }
    close() { this.source.close(); }
}
```

### 附录 A：资产指纹 / 过期检测（已记录，**MVP 后做**）

> 会议讨论后认为优先级不高，**作为 P1 任务**记录在案，未来需要时再实施。

#### A.1 目标

- 避免重复跑模型（同一首歌第二次打开能秒开）
- 检测"分析结果是否基于当前文件/模型"（UI 标 stale）

#### A.2 三个具体场景（为什么重要）

1. **重复打开同一首歌**  
   没有指纹 → 每次重跑 6 分钟  
   有指纹 → 对比 hash 一样 → 秒开

2. **用户换模型 / 改选项重新分离**  
   6 个 stem 文件被覆盖 → 旧的节奏/和弦分析**基于旧 stem** → 结果无效但 UI 不知道  
   有指纹 → 旧分析 meta 的 `input_hash` 跟新 stem 不匹配 → 标 stale → 弹窗

3. **用户升级 madmom 库**  
   旧分析是用 madmom 0.16 跑的，升级到 0.16.1 后直接显示旧结果，用户以为新算法更准  
   有 `plugin_version` 字段 → 版本不一致 → 标 stale

#### A.3 设计（30 行代码 + 3 个文件改动）

```python
# src/utils/fingerprint.py
import hashlib
from pathlib import Path

def audio_fingerprint(path: Path, head_bytes: int = 64 * 1024) -> str:
    h = hashlib.sha256()
    with path.open("rb") as f:
        h.update(f.read(head_bytes))
    return h.hexdigest()[:16]
```

改动：
- `raw_audio/<file>.meta.json` 新增 `"hash": "a3f2..."`
- `analysis_result/<plugin>/meta_<task_id>.json` 新增 `"input_hash"`, `"plugin_version"`
- `Workshop.load(path)` 启动时对比，emit `stale` 事件

工时：**0.3 人天**。

#### A.4 为什么暂缓

- 不会阻塞 MVP 演示
- 第一次跑就要走完整个 pipeline，指纹只在"重新打开"时才有价值
- MVP 演示场景下"打开同一首歌两次"是少数场景
- 留到 P1 阶段，**当用户开始抱怨"为什么每次都要重跑"时再实施**

#### A.5 触发再评估的信号

- 任何用户反馈"我昨天分析的歌今天打开又要等几分钟"
- 任何用户反馈"我换了模型怎么旧分析还在显示"
