# 剩余两项 P1 修改指南（已实施）

日期：2026-09-23。状态：已获批准并按核心方案实施；验证与实际差异见 `development_logs/bugfix-p1-task-audio-contract.md`。

本指南对应首次架构审查的两项 P1：后台任务生命周期不完整；音频内存和数组形状契约不稳定（含上传、URL 下载 IO）。以下保留审阅时的目标和设计作为实施依据；具体实现以代码、API 文档和开发日志为准。

## 1. 目标与范围

完成后应满足：

1. 每个后台任务可以查询、取消和追踪；同车间任务不会互相覆盖输入、状态和产物。
2. 只有结果文件与车间状态都成功持久化后，前端才收到一次成功终态事件。
3. 关闭、删除、退出服务会等待任务安全结束，再释放资源或删除文件。
4. 同一音轨即时分析与重启后分析使用相同的声道、采样率和数组格式。
5. 上传、下载不再整文件读入 bytes；下载和音频解码不阻塞 ASGI 事件循环。

沿用静态 Web UI、FastAPI/SSE、WorkshopCache、每车间 ExecutionContext 和进程级 GPU 信号量。继续采用逐插件任务模型；本轮不接通 AnalysisEngine 完整流水线，不引入任务队列服务或推理子进程，不进行大型模块拆分。

## 3. P1-A：任务生命周期

### 3.1 所有权与互斥

新增 `src/kernel/core/task_service.py`，由 Kernel 唯一持有。记录 task_id、workshop_id、任务类型、插件、音轨、输入版本、参数、状态、阶段、时间、错误及取消标记；同时保留执行任务、底层线程工作与 finalizer 的句柄。

职责边界：TaskService 负责接单、去重、状态机、取消和清理；Orchestrator 负责执行插件与资源准备；Workshop/Cache 负责业务状态和文件持久化。业务 started/done/failed/cancelled 事件由 TaskService 协调的单一提交入口发布。Orchestrator 只上报进度及执行结果。

同车间至多接受一个会改动音频或分析状态的工作。排他范围包含：接单 → 输入装载 → GPU 等待 → 推理 → 写结果 → 保存状态 → 终态。上传/URL 导入也占用该边界，阻止推理期间替换原音频。不同车间保留并行能力，GPU 任务继续受全局信号量约束。

重复策略：同一车间、同一输入版本和相同参数的在途请求返回已有 task_id，不启动第二次执行；冲突请求返回 409。已终结任务的显式重跑创建新 task_id。本轮不做自动重试。前端“全部分析”按每条任务的终态顺序提交。

### 3.2 状态和取消

建议运行状态：queued、running、committing、cancelling、done、failed、cancelled、interrupted。GPU 等待、下载、解码等用 stage 描述。持久化读取兼容旧状态；新增状态需同时更新 Workshop、HTTP 文档和 UI。

| 取消时机 | 规定行为 |
|---|---|
| 未开始实际执行 | 直接 cancelled，清理待执行工作 |
| GPU 等待中 | 退出等待，取消任务，不占用 GPU 许可 |
| 插件或下载工作中 | 进入 cancelling，尝试合作式取消，等底层工作真正退出 |
| 已进入 committing | 本次取消返回 409；提交是短暂不可取消阶段，关闭/删除等待提交结束 |
| 已终结 | 重复取消返回既有状态，不重复发终态事件 |

`asyncio.Task.cancel()` 不能强制停止正在 executor 中运行的同步模型。实现必须持有并等待底层工作完成，期间继续占有车间和 GPU 执行许可。取消后的迟到结果不得写入有效车间状态；被修改过的 RC 音频缓冲应在 worker 退出后失效，下次从已提交文件重载。

这意味着界面可能显示“正在取消，等待当前模型退出”。本轮不承诺即时终止不可中断模型；进程隔离与强制终止另行立项。

### 3.3 提交和事件

产物先写入任务独立的暂存目录，校验完成后发布到包含 task_id 的产物路径，最后原子保存 state.json，再发布 done。沿用相对路径字段，旧车间文件仍可读。

state.json 是产物是否有效的提交标记。多文件不能假定具备数据库事务；中断时允许留下未被 state 引用的孤立文件，启动恢复时清理它们。保存失败不得发 done，也不得覆盖上一份已提交产物。内存状态提交失败需要恢复至上次一致状态。

进度和终态统一携带 task_id、workshop_id、plugin，分析任务另带 track。前端按 task_id 接收当前任务事件，丢弃迟到事件。保证每个任务进程内仅发布一次终态；SSE 断线后通过查询接口恢复，不承诺网络层恰好一次投递。

### 3.4 关闭、删除和服务退出

- 切换车间：允许原任务继续，进度按车间过滤；切换不清理运行时。
- 关闭车间：标记 closing、拒绝新任务，取消并排空在途工作，再保存和释放上下文。
- 删除车间：标记 deleting、拒绝新任务，等待在途工作退出及提交结束，再删除目录；不得在推理仍写 RC/文件时删除。
- 服务退出：通过 FastAPI lifespan 调用异步 shutdown，先停止接单，排空工作，再停 autosave、保存状态并释放资源。同步 CLI/桌面入口使用安全适配，事件循环线程内不得同步等待自身。
- 超时策略：建议 30 秒作为告警阈值，超时继续显示/记录 draining 状态，不伪报关闭完成、不提前释放 GPU 或 RC。操作系统强制结束进程后，下次启动把遗留非终态改为 interrupted，不自动重跑。

### 3.5 API 与 UI 变化

保持 separate/analyze 原有 `ok`、`task` 字段与成功响应码，新增 `task_id`、`status` 和 `reused`。原 `task` 字段继续表示插件名称。

新增建议接口：

| 接口 | 用途 |
|---|---|
| `GET /api/tasks/{task_id}` | 查询任务/关闭删除操作状态 |
| `GET /api/workshops/{wid}/tasks` | 查询该车间任务，恢复刷新后的界面 |
| `POST /api/tasks/{task_id}/cancel` | 请求取消；返回真实当前状态 |

空闲车间关闭/删除保留原有 200 响应；有在途工作时返回 202 和 operation_id，客户端轮询操作直到结束，之后再移除车间。操作记录由进程级服务保留一段有界历史，删除车间后仍可查询该删除操作。

UI 增加取消入口和 cancelling/closing 状态，按 task_id 更新进度；“取消全部分析”同时停止后续提交并请求取消当前任务。服务重启后运行句柄不恢复；车间保存的任务记录用于展示 interrupted。

## 4. P1-B：音频格式、内存与输入 IO

### 4.1 内部音频契约

| 项目 | 统一规定 |
|---|---|
| RC 中的原音频和 stem | float32、二维 `(channels, samples)`；单声道为 `(1, samples)` |
| 采样率 | 正整数，与每个音频缓冲绑定；不得从另一缓冲的全局 sample_rate 猜测 |
| 时长/声道数 | `samples.shape[-1] / sample_rate` 与 `samples.shape[0]` |
| 模型需要单声道 | 插件适配层沿声道轴转换为一维 float32，再按模型要求重采样 |
| 文件读写布局 | 明确在 soundfile 等 IO 边界转置；不依据“某个维度小于 8”猜布局 |
| 非法输入 | 空数组、非有限数值、非法维度或采样率明确报错 |

建议新增 `src/audio/contracts.py` 提供布局转换、验证、单声道转换等共享函数。使用显式 layout 参数适配旧调用，内部标准数组重复经过适配时避免无意义复制。

RC 提供音频专用存取接口，把数组和采样率一起读写；保留通用 buffer 接口供非音频数据使用。迁移现行分离、和弦、节奏插件与 example 插件。对旧 loader、AnalysisEngine、播放器、可视化、MIDI 导出的调用点逐一确认，在兼容边界转换，避免更改公共数组布局后破坏旁路功能。

同会话分析和从磁盘恢复均装载标准音频，单声道转换只在相同的插件入口发生。原始音频与分离结果保留声道；模型重采样生成临时输入，不改写共享音轨。

### 4.2 分离器输出和内存

移除六份默认 float64 静音预分配；逐轨以 float32 读取模型实际输出，转换布局并验证。合法的全零输出仍是有效音轨；模型缺少承诺的 stem、轨名冲突或文件损坏应失败并列出原因，不补出伪造静音结果。

读取每份输出的真实采样率。若与原音频不同，明确重采样到本任务约定的原始采样率，再在时间轴上处理有限的模型 padding 差异。严重时长异常应报错，不能任意截断掩盖问题。padding 容差根据实际模型输出和回归样本确定并记录。

保存中间 stem 使用明确的无损浮点格式，避免默认 PCM 量化造成内存分析与重载分析输入不一致。现存 PCM 文件正常读取；不会批量重写旧缓存。

float32 立体声 PCM 每分钟在 44.1 kHz 下约 20.2 MiB，六轨约 121 MiB/分钟，尚未计入原音频与模型。此次消除额外占位数组、float64 与整文件 bytes 副本，但不宣称实现全流程流式推理或恒定内存。解码/分离前增加可配置预算检查，错误说明所需内存与可用预算；具体默认阈值在实现中记录，测试使用注入预算以避免机器差异。

### 4.3 上传、下载和落盘

- 本地上传按固定大小（建议 1 MiB）分块写入任务暂存文件，再通过文件路径导入缓存；计数检查大小并在失败/断连时清理临时文件。
- URL 标题获取、yt-dlp 下载、解码和较大的文件复制在受管理 worker 中运行。下载直接写入任务暂存目录，不再调用整文件 read_bytes()。
- 进度从 worker 通过安全事件桥回到主循环；导入占用车间任务许可，重入、关闭和删除都遵循 P1-A 的规定。
- 保留现有上传成功响应结构和等待导入完成的调用方式，工作在 TaskService 中注册。浏览器刷新可通过车间任务列表查到任务；请求断开后请求合作式取消并等待安全清理。
- 输入提交成功后更新输入版本，失效旧 RC 音频缓冲和旧分析关联；失败或取消时保留旧输入及其已提交结果。

## 6. 验收清单

使用可控制退出时机的 fake worker 验证并发与取消，避免靠固定 sleep 碰运气；音频使用短合成样本和临时文件。普通 CI 不下载权重或访问视频站点。

| 编号 | 必须证明的行为 |
|---|---|
| T1 | 相同在途请求仅执行一次；冲突请求 409，且未装载或覆盖 RC 输入 |
| T2 | 同车间锁覆盖输入至提交；不同车间 CPU 可并行；GPU 最大执行并发仍为 1 |
| T3 | 收到 done 时，所有引用文件和 state.json 都可读取；仅有一次终态 |
| T4 | 写文件/保存 state 失败时不发 done，旧产物保持有效，没有永久 running 状态 |
| T5 | 同步 worker 取消后继续运行期间，GPU 许可和上下文不提前释放；迟到结果不提交 |
| T6 | 推理中关闭/删除先进入等待；worker 结束后才清理，不重建已删除目录 |
| T7 | shutdown 停止接单并排空；告警超时不伪报已退出；强制退出后的非终态恢复为 interrupted |
| T8 | 断开 SSE/刷新后查询恢复；旧 task_id 进度和完成事件不能污染新任务 |
| A1 | mono、stereo、多声道、短片段都按明确布局转换；channels、duration 和采样率正确 |
| A2 | 内存 stem 与保存后重载 stem 进入同一插件时形状、采样率和数值在约定容差内一致 |
| A3 | 模型不同输出采样率得到正确时长；缺轨、错误轨名、异常时长明确失败 |
| A4 | 不分配六份占位静音；标准 stem 为 float32；通过 nbytes/分配观测确认额外内存下降 |
| A5 | 上传/下载不整文件读入 bytes；下载过程中其他 HTTP 请求和 SSE 仍可响应 |
| A6 | 导入取消、失败、超预算及中途关闭后临时文件清理，旧输入有效且无过期缓冲复用 |

实施后执行相关 Python 单元/集成测试、Node 前端测试、CI correctness Ruff 以及改动文件的适用规则和 diff 检查，再执行现有非 slow/network 基线。真实模型和 URL 下载单独记录环境、资产与结果；缺少权重或联网条件时明确列为未验证，不用 fake 测试冒充真实推理验证。

## 7. 本次请审阅的行为选择

本方案建议整体批准以下默认行为：同车间冲突请求拒绝而非后台排长队；重复在途请求复用 task_id；取消同步推理需等待安全退出；繁忙时关闭/删除返回 202；切换车间保留后台任务；分离缺轨明确失败；内部音频统一 float32 多声道，分析入口再转单声道。

用户批准本指南后开始代码实施。开发完成后按仓库开发指南与既定日志模板记录新 bugfix 的实际变更和验证结果。
